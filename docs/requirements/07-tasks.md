# 7. Tasks

The work that follows from the requirements, in the order the prioritization in [06-traceability-and-prioritization.md](06-traceability-and-prioritization.md) suggests. Each task traces to the requirements it implements or verifies, so that a finished task changes a requirement's status and an abandoned one leaves a visible gap.

Three other things in these documents are also called tasks, and they are elsewhere:

- What a player does with the site: the use cases in the [SyRS](05-system-requirements-specification.md).
- The solutions that satisfy stakeholders' goals: the tasks of the [goal model](03-goal-model.md), which are the features.
- Work deferred during bug fixing: `TODO.md`, whose one open item is T-10 here.
